01 / DOKUMENTACJA

Cel, odbiorca i zakres

Aplikacja pomaga studentowi przygotować wystąpienie o przewidywalnym czasie i dobrych proporcjach. Użytkownik planuje części, ćwiczy, zapisuje wyniki oraz otrzymuje informację, które fragmenty wymagają największej korekty. Interfejs nie ocenia jakości wypowiedzi, lecz zgodność rozłożenia czasu z własnym planem.

Scenariusz użytkownika

Student przygotowuje pięciominutową prezentację. Wstęp ma trwać 60 s, treść 180 s, a zakończenie 60 s. Pierwsza próba przekracza plan. Po skróceniu rozwinięcia student zapisuje drugą próbę, porównuje wyniki i wybiera konkretny fragment do dalszego ćwiczenia.

Zrealizowane funkcje

  • Wiele wystąpień z tytułem, własnym ID i uporządkowanym planem.
  • Dodawanie, przesuwanie i usuwanie części; planowane sekundy.
  • Stoper start/stop z możliwością wznowienia oraz ręczne wpisy.
  • Wiele kompletnych prób z numerem, czasami i notatką; edycja.
  • Porównanie każdej części oraz czasu całkowitego z planem.
  • Ranking rozbieżności i porównanie dwóch wybranych prób.
  • Własne wyszukiwanie liniowe i sortowanie przez wstawianie.
  • Liczniki operacji, rzeczywisty ślad i doświadczenia 10/100/1000.
  • Wersjonowany import/eksport JSON i pomocniczy zapis lokalny.
  • Trzy scenariusze oraz dobrowolny wykres zmian zgodności.

Kryterium sukcesu

Po jednej kompletnej próbie użytkownik zna największe odchylenie, jego kierunek i możliwą korektę. Po dwóch próbach widzi, czy suma rozbieżności zmalała. Gdy wyniki są równe, aplikacja podaje remis zamiast arbitralnego zwycięzcy.

Demonstracja działa lokalnie po rozpakowaniu. Aplikacja nie wymaga konta, serwera, mikrofonu, płatnego API ani połączenia z internetem.

Reguły i model danych

Zestaw jest obiektem JSON z polami format="stagewise", version=1 i trzema tablicami rekordów. Relacje wskazują identyfikatory, a nie pozycje w tablicy. Każdy rodzaj ma limit 1000 rekordów w całym zestawie.

Tabela 1. Rekordy i relacje.
RekordPolaPrzykład
Wystąpienieid, titleS-KONTROLA, Moje pierwsze wystąpienie
Częśćid, speechId, order, name, plannedSecondsP-WSTEP, S-KONTROLA, 1, Wstęp, 60
Próbaid, speechId, number, actualSeconds, noteA, S-KONTROLA, 1, {P-WSTEP:70,…}, notatka

Walidacja całego zestawu

ID są niepuste, unikalne w całym zestawie i niezmienne podczas edycji rekordu. Aplikacja generuje je lokalnie z prefiksu i UUID. Import dopuszcza 1–80 znaków A–Z, cyfr i łączników. Tytuł ma 1–160 znaków, nazwa części 1–100, a notatka do 4000 znaków.

Plan części to całkowite 1–3600 s, wykonanie to całkowite 0–7200 s. Zero oznacza pominiętą część, nie brak wpisu. Części mają kolejność 1…n bez luk i duplikatów. Próba zawiera dokładnie po jednym czasie dla wszystkich części tego wystąpienia. Numery prób są dodatnie i unikalne w wystąpieniu; nowy numer to największy zapisany plus jeden.

Niezmienniki i bezpieczeństwo stanu

Niekompletna próba pozostaje wyłącznie roboczym formularzem. Zmiana części planu wymaga nowego wystąpienia albo potwierdzonego usunięcia jego prób. Zmiana samego tytułu nie usuwa historii. Import sprawdza cały kandydat przed pytaniem o zastąpienie. Odrzucenie nie modyfikuje bieżącego zestawu.

Δᵢ = wykonanieᵢ − planᵢ; wynik = Σ|Δᵢ|. Dodatnie Δ oznacza przekroczenie. Teksty użytkownika są kodowane przy wyświetlaniu, nie wykonywane jako HTML.

Algorytmy i koszty

Dla p części jedna pętla oblicza Δ, sumę planu, sumę wykonania i Σ|Δ|. Koszt czasu wynosi O(p). Ranking powstaje we własnej funkcji insertionSort. Porównanie kluczy daje pierwszeństwo większemu |Δ|, a przy równości mniejszej kolejności części.

dla i = 1 … n−1:
    klucz = lista[i]; j = i−1
    dopóki j ≥ 0:
        licznik += 1
        jeżeli porównaj(lista[j], klucz) ≤ 0: przerwij
        lista[j+1] = lista[j]; j = j−1
    lista[j+1] = klucz

Posortowany prefiks rozszerza się o jeden klucz. Przesuwamy w prawo rekordy, które powinny znaleźć się za kluczem. Najlepszy przypadek: p−1 porównań, O(p). Najgorszy: p(p−1)/2, O(p²). Zwracana kopia listy zajmuje O(p); sam mechanizm przesuwania potrzebuje stałej liczby zmiennych.

Tabela 2. Przykład A: W=wstęp, T=treść, Z=zakończenie; 2 porównania.
PrzedDecyzjaPo
[W,T,Z], klucz=T|10| < |20|: przesuń W[W,W,Z], klucz=T
[W,W,Z]wstaw T na indeks 0[T,W,Z]
[T,W,Z], klucz=Z|10|=|−10|, W wcześniej: stop[T,W,Z]
sprawdzone = 0
dla rekord w próbach:
    sprawdzone += 1
    jeżeli rekord.id == ID: zwróć rekord, sprawdzone
zwróć brak, sprawdzone

Wyszukiwanie zwraca pierwsze dopasowanie. Licznik rośnie przy faktycznie sprawdzonym rekordzie. Początek listy wymaga jednego sprawdzenia, koniec i brak wyniku — n; czas O(n), pamięć dodatkowa O(1). Ślad sortowania kopiuje stan na potrzeby objaśnienia i jest dodatkowym narzutem, dlatego UI ogranicza go do 12 części.

Technologie i uruchomienie

Bez zależności w aplikacji

HTML, CSS i klasyczny JavaScript pozwalają uruchomić produkt bez budowania i bez sieci. Lokalne SVG są kodowymi zasobami interfejsu. Nie ma frameworka, zewnętrznych fontów ani bibliotek sortujących w głównej ścieżce. Moduły przeglądarkowe udostępniają jawne przestrzenie nazw; logika domenowa działa również w Node.js.

Uruchomienie z czystej kopii

git clone https://github.com/EdvinZe/asd1-m2-13-stagewise.git
cd asd1-m2-13-stagewise
# Otwórz index.html w przeglądarce.
node tests/run.cjs
node tools/benchmark.cjs

Po pobraniu ZIP wystarczy go rozpakować i otworzyć index.html. Node.js jest potrzebny tylko do automatycznych testów i benchmarku. Opcjonalny lokalny serwer: python3 -m http.server 8000 --bind 127.0.0.1. Nie jest konieczny do demonstracji.

Odtworzenie kontroli przeglądarki i dokumentów

npm ci
npx playwright install chromium
npm run test:browser
python3 tools/build_docs.py
node tools/export_pdf.cjs

Narzędzia używają przypiętych wersji Playwright i pdf-lib z package-lock.json. Generator treści wymaga Python 3, bez dodatkowych pakietów. Chromium potrzebuje bibliotek systemowych wymienionych w dokumentacji Playwright. Zmienne PLAYWRIGHT_MODULE, PDF_LIB_MODULE i CHROMIUM_PATH umożliwiają użycie wcześniej przygotowanych narzędzi.

Środowisko weryfikacji

Linux, Node.js 24.21.0, Python 3.12.3, Playwright 1.65.1 i Chromium 156. Testy przeglądarkowe otwierają rzeczywisty adres file:// i blokują HTTP/HTTPS. Zrzuty interfejsu pochodzą z tego przebiegu, nie z makiety.

Atomowość operacji

Transakcja kopiuje dane, wykonuje zmianę i sprawdza cały kandydat. Dopiero poprawny obiekt zastępuje stan w pamięci. Błędny import, brakujące czasy i niedozwolona edycja pozostawiają oryginał nietknięty. Wyniki są liczone ponownie po edycji, bez starego rankingu.

localStorage jest dodatkiem: dla file:// zachowanie zależy od przeglądarki, a przy dużych danych może zabraknąć limitu. Błąd zapisu jest widoczny, dane pozostają w pamięci. Podstawową kopią pracy jest eksport JSON. Limit pliku importu to 32 MB.

Obsługa i przykład kontrolny

Ścieżka: Plan wystąpienia → Nowa próba → Historia prób → Porównanie. W nowej próbie wybieramy część, uruchamiamy stoper i zatrzymujemy go, aby wpisać sekundy. Dopuszczalny jest także ręczny wpis. Po uzupełnieniu wszystkich części zapisujemy próbę i notatkę.

Tabela 4. Kontrolne dane i wyniki w sekundach.
CzęśćPlanAΔ ABΔ B
Wstęp6070+10600
Treść180200+20185+5
Zakończenie6050−1055−5
Razem300320+203000

Próba A: |10| + |20| + |−10| = 40 s. Ranking: treść, wstęp, zakończenie. Wstęp i zakończenie mają równy moduł, więc rozstrzyga kolejność. Próba B: 0 + 5 + 5 = 10 s. B jest bliższa planowi o 40−10 = 30 s.

Przykład pośredni: dla treści A odejmujemy 180 od 200, otrzymując +20 s. To największy moduł, więc treść zajmuje pierwsze miejsce rankingu. Zmień w B wstęp z 60 na 90 s: wynik B wzrośnie do 40 s i pojawi się remis.

Na pulpicie kolorom towarzyszą podpisy „za długo”, „za krótko” i „zgodnie”. Formularze mają etykiety, obsługę klawiaturą oraz widoczny fokus. Układ został sprawdzony przy szerokościach 390, 768 i 1512 px.

Wnioski, źródła i wkład

Wnioski

Najważniejszą informacją jest suma bezwzględnych odchyleń, a nie sam czas łączny. Ranking przekłada tę miarę na praktyczne wskazówki. Prosta lista rekordów i jawne algorytmy są wystarczające dla zakresu projektu; licznik pokazuje różnicę między liniowym wyszukiwaniem a kwadratowym najgorszym przypadkiem sortowania.

Ograniczenia i możliwy rozwój

Aplikacja ocenia czas, nie retorykę ani jakość argumentów. Brak synchronizacji, kont i rozpoznawania mowy jest świadomym ograniczeniem zakresu. Stoper liczy pełne sekundy i używa zegara performance.now; uśpienie systemu może zależeć od implementacji przeglądarki. Dla długich lub ważnych prób należy zweryfikować wynik ręcznie. Nie należy polegać wyłącznie na localStorage.

Możliwe rozszerzenia to statystyki mediany odchyleń i archiwizacja wersji planu. Dobrowolny wykres postępu został już dodany. Nie zastępuje on wymaganych tabel i obliczeń.

AI i rzeczywisty wkład

Wykorzystano asystenta OpenAI Codex w OpenClaw do przygotowania kodu, stylu, testów, generatora dokumentów i materiałów do obrony. Automatyczne testy i zrzuty uruchomił asystent. Zlecający wybrał temat oraz kierunek wyglądu: czerwienie i ciemne szarości, a także dostarczył logotypy UwB. Nie przypisujemy studentowi niepotwierdzonych samodzielnych zmian ani wykonania testów.

Przed oddaniem autor powinien samodzielnie przeczytać kod, uruchomić program i testy oraz przećwiczyć zmianę danych i reguły porównania. Przygotowane notatki wyjaśniają fragmenty wymagane na obronie.
